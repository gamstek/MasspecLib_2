# MasspecLib2：Windows 新手启动指南

**这份包用于在 Windows 电脑上打开管理员端，连接公司已有服务器。**

适用：Windows 10/11、x64 电脑。软件版本为 2.8.67。无需在自己的电脑上安装 MySQL、Python、Conda、WiX，也无需进入 Linux 服务器执行命令。

本包是源码启动版，不包含现成 EXE 和 npm 依赖。第一次启动会联网下载依赖和桌面运行环境，再自动编译；后续启动通常可以复用这些文件。**公司连接配置和软件账号需要管理员提供，公开源码中不包含真实连接密码。**

## 开始前：只解压一次

1. 将整个 ZIP 解压到一个固定文件夹，例如 `D:\MasspecLib2`。
2. 打开解压后的项目文件夹。你应该在同一层看到 `README.md`、`启动软件.cmd`、`连接配置`、`package.json`。
3. 不要在压缩软件里直接运行启动脚本，不要只把一个 CMD 文件拷到桌面。路径中有空格和中文也可以运行。

## 第 1 步：安装 Node.js（只做一次）

打开官方页面：<https://nodejs.org/zh-cn/download>

- 选择 **Node.js 24.x、Windows、x64、MSI 安装程序**。此启动脚本也接受 22.13 以上的 22.x。
- 安装时保持默认选项，确保包含 npm 和 PATH。
- 仅连接公司服务器不需要选装 Python / Visual Studio 等原生模块构建工具。
- 安装完成后关闭安装窗口，再重新双击本项目的启动脚本；不必手动配置系统环境变量。

不确定装好没有：在项目文件夹双击 **`检查环境.cmd`**。若提示找不到 Node.js，重新安装或重新登录 Windows 后再试。

## 第 2 步：放入公司连接配置（只做一次）

请直接把下面这段发给公司管理员：

> 我要从源码运行 MasspecLib2 管理员端，请提供与公司当前服务器匹配的 `admin-profile.json`、`shared-server.json`，以及我的软件登录账号。请确认我的电脑能访问对应网络或 VPN，并确认服务端与本软件兼容。

将管理员给的两个原文件放到 **`连接配置` 文件夹**，不要修改文件里的密码或指纹：

```text
项目文件夹/
├─ README.md
├─ 启动软件.cmd
├─ 检查环境.cmd
├─ package.json
└─ 连接配置/
   ├─ 放置配置文件.txt
   ├─ admin-profile.json       ← 管理员提供
   └─ shared-server.json       ← 管理员提供
```

- 管理员配置也支持名为 `delivery-profile.json`，不需要自己改名。
- 如果管理员端已经安装且能正常登录，可让管理员从该安装目录的 `resources` 文件夹提供 `delivery-profile.json` 和 `shared-server.json`。安装目录可通过桌面快捷方式的“打开文件所在的位置”找到。
- 不要把 `resources/shared-server.example.json` 改名当作实际配置。它的 `enabled:false` 表示占位，不能连接公司。
- 软件账号不是 GitHub 账号，SSH 登录信息也不是 GitHub SSH 密钥。不要把 GitHub Token 填到这些文件里。
- **真实配置可能包含数据库或 SSH 连接信息，应私下交接，不要上传 Public 仓库。** 本项目已忽略 `连接配置` 下的 JSON 文件。

## 第 3 步：双击启动

1. 连接公司网络或管理员指定的 VPN。
2. 先退出已安装的同版本管理员端，避免打开旧程序窗口。
3. 双击 **`启动软件.cmd`**。
4. 第一次会显示四步：安装依赖 → 下载 Electron → 生成并编译程序 → 打开管理员登录窗口。下载期间保持联网，不要关闭命令窗口。
5. 出现 **“管理员登录”** 窗口后，输入管理员分配的软件账号和密码。
6. 登录成功后进入数据库工作台。是否显示某个库由服务器登记、工作台设置和账号权限决定，本源码包不自带公司完整谱库。

以后使用仍双击同一个 `启动软件.cmd`。脚本会检查依赖及源码是否变化，必要时重新构建。关闭软件后命令窗口会退出；不要在运行期间移动项目文件夹。

## 我怎么知道运行成功？

- **本机启动成功**：看到“管理员登录”窗口。这一步不代表账号或公司网络已经验证。
- **连接公司成功**：使用真实账号登录后，看到工作台、数据库列表，并能打开有权限的化合物详情。
- 若能登录但没有数据库，先请管理员确认工作台默认库和发布状态，不要在本机随便新建或删除数据库。

## 常见问题

| 提示 / 现象 | 处理方式 |
| --- | --- |
| 找不到 Node.js / 版本不符合 | 安装 24.x x64，再重新打开脚本。不要用旧 Node.js 或 32 位版本。 |
| 缺少公司连接配置 | 按第 2 步获取两个文件，放到 `连接配置`。脚本会在下载安装前停止，不会跳到本地 MySQL 模式。 |
| JSON 配置无法读取 | 将管理员给的原文件重新放入，不要用 Word 修改文件。 |
| shared-server.example 不能用 | 这是空样例；必须获取实际 `shared-server.json`。 |
| 出现 npm warn 或 npm 更新提示 | 这些提示不一定表示失败。先等待脚本结束，不需要手动升级 npm；若最后显示“启动未完成”，再查看具体错误。 |
| 首次安装下载很慢 / npm 网络错误 | 检查联网和公司代理。中断后可再次运行；失败信息保存在 `logs/启动日志.txt`。不要因此删除公司的数据库。 |
| Electron 下载失败 | 保持联网后重新运行。脚本会单独检查并下载 Electron，不要求编译可选的 cpu-features 模块。 |
| 提示脚本文件不存在 | 可能只复制了 CMD，或仍在 ZIP 内。完整解压整个项目，再启动。 |
| 提示管理员版本配置不正确 | 可能拿到了客户端配置。向管理员重新索取管理员端配置。 |
| 证书不匹配 / 公钥不正确 | 向管理员核对当前服务地址、证书和签名公钥。不要自行关闭证书检查。 |
| SSH 认证失败 / 连接超时 | 先核对公司网络、VPN、端口和管理员提供的连接方式；在登录页“连接诊断”里查看。 |
| 账号或密码错误 | 使用软件管理员分配的账号。默认显示的账号文字不代表该账号一定可用。 |
| 启动后激活了另一个旧窗口 | 退出旧版管理员端和托盘里的旧程序，再启动本项目。 |

需要维护人员处理时，提供软件窗口的报错或日志最后几十行；不要发送真实配置文件、密码、Token 或私钥。

## 维护人员：脚本做了什么？

启动入口为 `scripts/novice-start.cjs`。它只操作当前源码包的依赖和构建文件，不会初始化 MySQL，不会修改公司服务器或原始谱库。

```bat
node scripts/novice-start.cjs --check
node scripts/novice-start.cjs --prepare-only
node scripts/novice-start.cjs --rebuild
```

- `--check`：只检查本机版本和配置文件结构，不联网登录，不下载安装。
- `--prepare-only`：安装并构建，但不打开软件窗口，供维护人员验证使用。
- `--rebuild`：强制重新生成并编译，之后正常启动。
- 配置由 `MASSPECLIB2_DELIVERY_CONFIG` 和 `MASSPECLIB2_SHARED_PROFILE` 传入子进程，不把私有文件拷进 `resources`，也不打印配置内容。
- 首次依赖安装使用锁文件和 `npm ci --include=dev --ignore-scripts`；随后显式下载 Electron，并执行 `db:gen`、类型检查和构建。`db:gen` 在此配置下只生成 Prisma 代码，不连接数据库。
- 当前电脑下的依赖、源码指纹和构建状态保存在 `.runtime/novice/`。`node_modules`、`out`、日志、连接配置及 `.runtime` 都不应提交到公开仓库。
- 需要运行单元检查时执行：`node --test tests/novice-start.test.cjs`。

服务器部署、生成正式管理员 MSI 和客户模板属于维护人员操作，见 [服务器部署说明](docs/server-deployment.md)。原 README 保留在 [docs/README_原版.md](docs/README_原版.md)。

这份启动包的检查范围和实际执行结果见随包 `验证说明.txt`。是否能访问公司数据，最终需要用管理员提供的真实配置和账号在公司网络中核对。
