# MasspecLib2 2.3.0：数据库自动检查、色谱图与选择导出

## 使用方式

继续使用原来的 `masspeclib2` 虚拟环境和项目 `ptk-master2`。本次未新增 npm 依赖，原生谱库仍为结构4。已经安装依赖时无需重新执行 `npm ci`。

Windows 源码运行或生成 MSI：

```bat
conda activate masspeclib2
cd /d F:\MasspecLib2\ptk-master2
npm run db:gen
npm test
npm run typecheck
npm run build:win -- --publish never
```

生成的安装包位于 `dist\MasspecLib2-2.3.0-x64.msi`。如使用随附的 Windows 目录预览包，解压全部内容后打开 `MasspecLib2.exe`；该包不是 MSI。升级前关闭旧程序，原数据库和用户配置不需删除。

## 软件中的变化

- 化合物列表增加数值色谱、色谱图片、定量结果、离子响应等数据类型筛选，以及异常、数据不足、待检和异常待复核筛选。多种数据类型同时选中表示同时具备。
- 详情页依次包含“详细信息”“谱图与质谱方法”“色谱图”。在“色谱图”中按来源、方法、样品查看轨迹、图片和测定记录；可查看检查依据、历史快照并记录人工复核。
- “检测结果”默认显示数据库自动检查；原有手动文件导入保留在“文件导入与历史”中。
- 连接启用的数据库后自动开始扫描，默认每60秒核对一次。软件关闭时不运行；扫描完成后再计算下一次间隔。首次完整扫描前仍使用原列表，数据类型筛选需等索引完成。
- 检查针对一条轨迹或测定结果；化合物列表只汇总状态，不把一个样品的异常推广为该化合物的固有性质。
- 仅参考质谱不进入色谱、浓度或离子比检查；仅图片可查看但峰形为“数据不足”。没有测定浓度/适用限量、没有定性和定量响应/参考比，分别显示数据不足或不适用。
- 一个记录中多个定性通道分别判定并汇总，任一通道不满足会保留异常；支持相对和绝对偏差。数据与规则属于同一方法和同一测定，不从其他来源拼接面积计算离子比。

异常筛选只影响查看，不自动删除、不合格剔除或改写原始数据库。峰形结果属于规则筛查，“疑似分叉／肩峰”等需要复核；数值超限不等同于最终合规结论。

## 来源数据库与审核库

来源是数据的公开库或本地库名称，SQL数据库是物理存储，两者相互独立。一个数据库可以收集多个来源，一个来源也可以分布在多个数据库。

原生谱库结构4继续保存化合物、分类、来源、质谱和液相梯度。本版额外使用两类表：

1. **来源库的可选实验扩展表**：`experiment_results`、`chromatogram_traces`、`experiment_rules`。可直接通过 Navicat 写入，无需使用软件的“导入检测数据”。这些表不会被软件自动添加到每个来源库；表已存在且格式不同则配置字段映射。
2. **独立审核库**：默认 `mspec_lib2_audit`，保存 `qc_entities`、`qc_members`、`qc_assets`、`qc_checks`、`qc_reviews`、`qc_scans`、`qc_merges` 和 `qc_meta`，结构版本1。保存索引、判定、输入和规则快照、复核及关联历史。

在“检测结果 → 自动检查设置”中选择审核库服务器连接和独立库名。该连接的账号必须能创建/使用审核库并写入审核表；软件拒绝使用含其他业务表的库作为审核库。来源连接可设为只读。配置错误会显示在页面，原有谱库浏览仍可使用。

可用“暂停自动检查”暂停本次及后续周期，当前批次结束后生效；点击“立即检查数据库”恢复本轮。需要重启后也停用时，在设置中关闭“启用自动检查”并保存。间隔支持30—86400秒。

## 给数据建设方的最小约定

标准建表文件：`src/main/audit/experiment-schema.sql`，交付目录另附 `可选实验扩展结构1.sql`；Windows包资源目录中为 `resources/database/experiment-schema-v1.sql`。在**已经初始化为结构4的来源库**中执行。不要用其替换原生谱库初始化SQL。

| 表 | 关键字段 | 用途 |
|---|---|---|
| `experiment_results` | `id`、`compound_id`、`source_library_id`、`batch_name`、`method_name`、`rule_version`、`record_type`、`status`、`data` | 样品/参考测定结果，`data`为检测JSON |
| `chromatogram_traces` | `id`、`compound_id`、`experiment_result_id`、`source_library_id`、`method_name`、`channel_role`、`time_unit`、`points`、`image_base64`、`data`、`status` | 独立色谱或与测定结果关联的定量/定性轨迹 |
| `experiment_rules` | `id`、`method_name`、`matrix`、`rule_version`、`active`、`data` | 可选的方法规则；同方法、同基质应有唯一适用规则 |

- `compound_id`必须对应当前来源库的化合物ID；不同库都存在ID=1没有关系。
- `source_library_id`对应当前库的 `spectral_libraries.id`，建议每条实验数据明确填写。没有明确来源且化合物属于多个来源时，软件不会擅自分配实验数据来源，限定来源的查询中不会计入这类记录。
- `status='completed'`才参与检查，`draft`等状态不参与。先写入曲线和规则，确认完成后再改状态。
- `record_type`区分sample/reference，检查适用性主要由实际数据和 `data.checks`决定，不按化合物类别强行检测。
- `points`为时间—强度数组，时间严格递增，`time_unit`必须明确为min或s，强度不可使用m/z替代；每条曲线最多100000点，每条测定记录总曲线点数最多500000。
- `image_base64`使用PNG/JPEG/WebP/GIF的 `data:image/...;base64,...`；图片不能用于准确峰形计算。
- `experiment_result_id`只能关联同库、同化合物、同方法和一致来源的测定。`channel_role`标准支持quantifier、qualifier；额外定性通道在结果JSON的qualifiers数组中明确指定。
- `data.checks`可选，如 `["peak","ratio","limit"]` 明确声明应检查的项目；适用但缺数据则标记数据不足。省略时按实际字段推导，空数组表示不检查该记录。只含参考质谱的记录不应声明这三类检查。
- 为控制内存，读取前先核对体积，大批次自动按化合物拆分；单个化合物本轮实验数据超过32MiB或10000条时会提示按检测批次建立视图接入，不截断后假装完成。
- 数据库重扫会对内容和规则计算指纹；即使未更新业务更新时间，内容变化仍会被识别。完整扫描期间需要读取相关数据；只有发生变化的记录才重新计算，不是每轮对所有化合物重新分析。

`experiment_results.data`示例（数值仅演示）：

```json
{
  "sample": "演示样品A",
  "matrix": "演示基质",
  "expectedRt": 5.0,
  "rtWindow": 0.5,
  "checks": ["peak", "ratio", "limit"],
  "trace": {
    "timeUnit": "min",
    "points": [
      {"time": 4.5, "intensity": 0},
      {"time": 5.0, "intensity": 100},
      {"time": 5.5, "intensity": 0}
    ]
  },
  "measurement": {"value": 0.12, "unit": "mg/kg", "modifier": "value"},
  "limit": {"value": 0.1, "unit": "mg/kg", "source": "演示限量规则，不适用于真实判定"},
  "ratio": {
    "quantifierArea": 1000,
    "qualifierArea": 500,
    "reference": 0.5,
    "tolerancePct": 20,
    "referenceSource": "同方法参考标准"
  }
}
```

上面的三个点只说明格式，采样不足会被标记，实际检测应提供完整轨迹及足够采样点。实测离子比为定性/定量面积；参考比0.5且相对偏差20%表示0.4—0.6。绝对偏差改用 `toleranceMode:'absolute', toleranceAbsolute:0.05`，表示0.45—0.55，不解释为5%。不提供适用限量、单位、基质依据时，不自动补造限量。

方法规则通过 `experiment_rules` 中同 `method_name` 和适用 `matrix` 匹配；显式记录值优先，峰形规则按字段补充。同一方法匹配多条有效规则时显示需确认，避免任意采用其中一条。

已有业务表格式不同，可在“数据库管理 → 编辑连接 → 检测数据字段映射”中填写一次配置，例如：

```json
{
  "table": "assay_results",
  "key": "result_id",
  "compoundKey": "analyte_id",
  "completedValue": "done",
  "fields": {
    "status": "record_state",
    "sample": "sample_name",
    "concentration": "concentration",
    "unit": "concentration_unit",
    "limit": "maximum_value",
    "limit_unit": "maximum_unit",
    "limit_source": "rule_reference"
  }
}
```

也可把 `data`映射到包含上述标准检测JSON的列，把 `trace_json`、`qualifier_trace_json` 映射到标准轨迹JSON对象列。表名和列名须真实存在、记录键唯一、化合物外键有效；不是自动猜测任意SQL结构。每个连接配置一张自定义结果表；复杂多表格式需先建立视图或整理成标准扩展表。

## 同一化合物跨库展示

采用逻辑关联，不删除、搬移或覆盖来源记录。

- 自动关联仅使用完整InChIKey，且不带身份冲突标记、不存在分子式冲突。名称、CAS相同不自动合并。
- 列表勾选两条记录后，可“关联为同一化合物”，填写确认人及依据。操作前暂停自动检查；在“检测结果 → 扫描记录与身份关联历史”中可撤销尚无后续成员变化的关联。
- 同一化合物的不同来源谱图、液相方法和实验数据集中展示，各自保留记录ID和来源。一个来源有色谱、另一个来源有质谱，关联后的化合物会同时具有这两种数据标签。
- 统一详情有多条原记录时只做集中查看，通过来源记录入口进入原记录编辑。只含一条记录时仍按原连接权限编辑。
- 来源和数据库筛选约束汇总和色谱内容，不拿范围外的数据充数；未明确来源的数据不在限定来源结果中强行计入。
- 来源读失败不删除未扫描记录，保留旧索引并提示可能过期。记录或子数据在一次成功完整扫描中消失后，从当前结果移除，旧检查与复核历史继续保存。

化合物“分类”仍是独立的化学/用途目录；“有色谱”“异常”等属于数据标签和结果状态，不改写农药、药物等分类。

## 选择字段和内容导出

在“全部化合物 → 导出化合物”中选择当前筛选结果或当前页勾选记录，再选择格式、基础字段和关联内容。“检测结果 → 数据库自动检查 → 导出筛选结果”也可勾选样品、判定、测定值、离子比、复核、色谱数值等字段，仅导出符合当前异常筛选的记录。

- JSON：推荐用于数值色谱、谱峰、完整梯度和检查记录，保留嵌套结构。
- CSV / Excel：用于字段报告；关联内容放入JSON单元格。Excel单元格超过32767字符会提示改用JSON，不截断曲线。
- 可勾选中文名、英文名、主名称、CAS、分子式、质量、同义词等；内容包括来源、分类、质谱方法、液相方法与梯度、谱图、色谱与测定记录、检查及复核。
- 取消的内容不作为隐藏的原始行附带。记录标识始终导出，便于核对。最多10000条，更多数据通过筛选分包。
- 字段报告不是 `.msldata` 导入包。完整原生谱库迁移继续使用MSLDATA，保留依赖关系而不裁剪字段；新增实验扩展表与审核库须单独备份，不能依靠原生迁移包迁移它们。
- 检查内容导出当前判定及复核；历次数据快照在“色谱图 → 历次检查”中查看，完整历史通过备份审核数据库保存。

## Navicat演示：从建库开始

演示位于 `examples/audit`，交付另提供压缩包。数据均为模拟；第一条化合物使用人工格式的身份键，仅演示自动关联，不是真实InChIKey。

1. 用Navicat连接你的MySQL服务器；主机、端口、用户名、密码使用你自己已经能连接成功的配置。
2. 执行 `00_建立两个专用空库.sql`，建立 `mspec_lib2_auto_demo_a` 和 `mspec_lib2_auto_demo_b`。同名库已存在时停止，换用新的空演示库；不要在业务库执行后续初始化脚本。
3. 执行 `01_初始化并填充演示甲库.sql`、`02_初始化并填充演示乙库.sql`，各执行一次。脚本包含原生结构4、可选实验结构和模拟数据，不需要额外使用软件导入。任何报错都应先停止并核对。
4. 执行 `03_只读核对.sql`：甲、乙各8条化合物；乙库15条completed测定、1条draft和1条仅图片色谱。
5. 在软件“数据库管理”新增这两个原生连接，填写实际MySQL主机/端口/账号；数据库名分别填写上面两个名字，启用并测试连接。仅测试时可先停用其他测试库，避免混入总数。
6. 在“检测结果 → 自动检查设置”选择有权限的连接和独立审核库名，保存。等首次扫描完成，也可点击“立即检查数据库”。
7. 仅启用这两个库时，统一列表应有15个化合物：两库各8条，其中第一条通过演示身份键关联。第一条有两库谱图、乙库数值色谱和图片；分类和液相梯度仍可查看。
8. 检测结果有16条：15条测定和1条仅图片记录。预期前延1条、拖尾3条、疑似分叉1条、数值超限2条、离子比不满足2条；这些异常会重叠，不应相加成总条数。仅图片为峰形数据不足，draft不参与。
9. 在Navicat修改乙库的一条测定值，提交后等待一个检查周期，或点击立即检查。查看新结果及历史快照；原复核不被覆盖。修改的是来源库，检查记录存储在审核库，Navicat刷新对应表即可看到。
10. 在化合物列表勾选记录，导出时只勾CAS/分子式，验证没有额外谱图和色谱；再单独勾选色谱、液相梯度和检查内容，验证能输出相应内容。

## 本次验证范围

进行了类型检查、单元/页面模板测试、生产构建、真实MySQL与真实Worker的接口集成，以及交付SQL原文的临时库执行。生产集成用Electron桌面接口替身，不能替代Windows真实窗口、安装和实际仪器数据验证。峰形筛查仍需使用实验室标注数据评估误报漏报，并按具体方法确认阈值。
